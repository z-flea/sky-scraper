# 对话记录：实现建筑动态颤动系统

**日期**：2026-02-08
**项目**：game3 (Sky Scraper 摩天大楼游戏)
**主题**：为游戏添加建筑动态颤动/晃动系统

---

## 对话概要

本次对话实现了 Sky Scraper 游戏的建筑动态颤动系统，让大楼在楼层落地后产生物理真实的左右晃动效果。

## 关键决策

### 1. 物理模型选择

**初始方案**：累积速度模型
- 每次楼层落地时累加速度
- 包含共振检测机制
- 问题：导致摆动不断累积，即使交替方向落地也会加强

**最终方案**：重心偏移模型 ✅
- 实时计算塔的重心位置
- 大楼向重心方向倾斜
- 交替落地会让大楼回正，而不是累积摆动
- 更符合真实物理和用户期望

### 2. 视觉效果实现

**枢轴旋转方案** ✅
- 以"最高层向下数10层"为枢轴点
- 枢轴以下：不旋转
- 枢轴以上：递增旋转（模拟弯曲）
- 避免了"整根棍子倾斜"的不真实效果

### 3. 相机处理

**决策**：禁用相机抖动 ✅
- 原有的相机抖动基于 instability
- 与建筑晃动混在一起导致画面混乱
- 最终禁用相机抖动，只保留建筑本身的晃动

## 实现细节

### 核心文件修改

1. **Physics.js** ([src/core/physics.js](../../src/core/physics.js))
   - `calculateStiffness(floorCount)`: 计算刚度（0.4 → 0.1）
   - `calculateTowerCenterOfMassOffset(floors)`: 计算重心偏移
   - `calculateTargetSwayAngle(comOffset, floorCount)`: 计算目标角度
   - `updateTowerSway(...)`: 更新摆动物理
   - `checkSwayCollapse(swayAngle, floorCount)`: 检查摆动倒塌

2. **Game.js** ([src/core/game.js](../../src/core/game.js))
   - 添加全局摆动状态：`towerSwayAngle`, `towerSwayVelocity`
   - `update()`: 实时计算重心并更新摆动
   - `applySwayVisuals()`: 应用枢轴旋转视觉效果
   - `releaseFloor()`: 检查摆动倒塌

3. **Camera.js** ([src/rendering/camera.js](../../src/rendering/camera.js))
   - 禁用相机抖动效果
   - 保持画面稳定

### 关键参数

```javascript
// 刚度（随楼层降低）
stiffness: 0.4 (1-20层) → 0.1 (100+层)

// 敏感度（重心偏移转角度）
sensitivity: 0.15 (基础) → 0.35 (高层)

// 阻尼
damping: 0.08

// 倒塌阈值
maxAngle: 15° (20层以下) → 7° (100层以上)

// 视觉弯曲
bendOffset: sin(angle) × heightRatio × 1.0
```

## 迭代过程

### 第一版：快速抖动
- **问题**：阻尼太大（0.95），摆动1秒内停止
- **表现**：快速抖动而不是缓慢晃动
- **调整**：降低阻尼到0.98，降低刚度

### 第二版：累积摆动
- **问题**：速度累积模型导致摆动不断加强
- **表现**：交替方向落地仍然加强摆动
- **调整**：改为重心偏移模型

### 第三版：画面晃动
- **问题**：相机抖动和建筑晃动混在一起
- **表现**：整个画面看起来在晃动
- **调整**：禁用相机抖动

### 最终版：完美效果 ✅
- 建筑根据重心左右晃动
- 画面保持稳定
- 吊臂和其他物体不受影响

## 技术亮点

   - 基于重心偏移的倾斜

2. **视觉效果**

   - 避免了"棍子倾斜"的不真实感

3. **性能优化**
   - 只计算顶部10层的重心
   - 全局状态避免每个楼层单独计算
   - 视觉效果只应用于已落地楼层
