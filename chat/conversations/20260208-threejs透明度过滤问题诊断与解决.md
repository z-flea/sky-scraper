# Three.js透明度过滤问题诊断与解决

## 背景

在 Sky Scraper 游戏项目中，吊线（cable）纹理设置了 `alphaTest` 来过滤透明像素，但透明度过滤仍然无效，吊线周围显示出不应该存在的灰色矩形背景。

## 目标

- [x] 诊断透明度过滤失败的根本原因
- [x] 修复代码中的参数冲突
- [x] 清理纹理文件中的问题像素
- [x] 验证透明度过滤效果

## 问题诊断过程

### 1. 代码层面的问题

通过深度分析代码，发现了多个相互冲突的参数设置：

#### 问题 1：`transparent: false` 与 `alphaTest` 冲突
- **位置**：`src/rendering/scene.js:137`
- **问题**：`transparent: false` 告诉 Three.js 材质完全不透明，不需要读取 alpha 通道
- **影响**：`alphaTest` 完全无效，因为没有 alpha 数据可供测试

#### 问题 2：`LinearFilter` 导致边缘插值
- **位置**：`src/rendering/scene.js:97-98, 151-152`
- **问题**：线性过滤会在透明和不透明像素之间进行插值，产生半透明像素
- **影响**：边缘出现"光晕"或"毛边"

#### 问题 3：缺少 `premultipliedAlpha` 设置
- **问题**：Three.js 默认假设纹理使用预乘 alpha，但 PNG 通常不是预乘的
- **影响**：透明边缘可能显示出错误的颜色

#### 问题 4：`alphaTest` 阈值过低
- **位置**：`src/rendering/scene.js:139`
- **问题**：`alphaTest: 0.1` 太低，会保留几乎所有半透明像素
- **影响**：半透明区域仍然可见

### 2. 纹理层面的根本问题（关键发现！）

使用 `magick identify -verbose` 分析纹理文件，发现了**根本原因**：

```bash
Colorspace: sRGB
Type: TrueColorAlpha
Alpha: 1-bit  # 只有完全透明或完全不透明
```

**关键发现**：纹理中的灰色区域是**不透明的灰色像素**（RGB=灰色，alpha=1），不是半透明像素！

- ❌ 错误理解：灰色区域是半透明的（alpha < 1）
- ✅ 实际情况：灰色区域是不透明的灰色像素（alpha=1）

**这就是为什么 `alphaTest` 无法过滤它们** - 因为它们的 alpha 值是 1（完全不透明）！

## 解决方案

### 代码修改（3 处）

#### 1. 修改吊线材质设置
```javascript
// src/rendering/scene.js:136-141
const cableMaterial = new THREE.MeshBasicMaterial({
  transparent: true,      // ✅ 改为 true，启用 alpha 通道读取
  side: THREE.DoubleSide,
  alphaTest: 0.9,        // ✅ 提高到 0.9，只保留几乎完全不透明的像素
  depthWrite: true
});
```

#### 2. 修改吊线纹理加载
```javascript
// src/rendering/scene.js:147-162
this.textureLoader.load('/assets/sprites/dom/cable.png', (texture) => {
  texture.premultipliedAlpha = false;  // ✅ 禁用预乘 alpha
  texture.minFilter = THREE.NearestFilter;  // ✅ 使用最近邻过滤
  texture.magFilter = THREE.NearestFilter;  // ✅ 避免边缘插值
  // ...
});
```

#### 3. 修改楼层纹理加载
```javascript
// src/rendering/scene.js:93-113
this.textureLoader.load(file, (texture) => {
  texture.premultipliedAlpha = false;  // ✅ 禁用预乘 alpha
  texture.minFilter = THREE.NearestFilter;  // ✅ 使用最近邻过滤
  texture.magFilter = THREE.NearestFilter;  // ✅ 避免边缘插值
  // ...
});
```

### 纹理文件清理（关键步骤！）

使用 ImageMagick 将**不透明的灰色像素转换为透明像素**：

```bash
magick cable_backup.png \
  \( +clone -fill black -colorize 100% \) \
  \( -clone 0 -colorspace gray -negate -threshold 80% \) \
  -delete 0 -alpha off -compose copy-opacity -composite \
  cable.png
```

**效果**：
- 文件大小：7.6MB → 19KB（减少 99.7%）
- Alpha 通道：1-bit → 8-bit（真正的透明度）
- 内容：只保留黑色吊线，其他区域完全透明

## 技术原理

### `alphaTest` 的工作原理
```javascript
if (pixel.alpha < alphaTest) {
  discard;  // 丢弃像素，不渲染
} else {
  render;   // 渲染像素
}
```

### 为什么之前无效？
1. **`transparent: false`** → Three.js 不读取 alpha 通道 → `alphaTest` 无数据可测试
2. **灰色像素 alpha=1** → 即使读取 alpha，灰色像素的 alpha 值是 1 → 通过 `alphaTest` 测试 → 被渲染

### 解决方案的协同作用
1. **代码修改** → 启用 alpha 通道读取和测试
2. **纹理清理** → 将灰色像素的 alpha 设置为 0
3. **结果** → `alphaTest` 正确过滤 alpha=0 的像素

## 关键收获

1. **`transparent` 和 `alphaTest` 必须配合使用**
   - `transparent: true` 启用 alpha 通道读取
   - `alphaTest` 设置过滤阈值
   - 两者缺一不可

2. **纹理本身的质量至关重要**
   - 不透明的灰色像素无法通过代码过滤
   - 必须在纹理层面解决问题
   - 使用工具验证假设，不要仅凭视觉判断

3. **过滤器选择影响边缘质量**
   - `LinearFilter` 会产生半透明边缘（插值效果）
   - `NearestFilter` 保持像素完美的边缘（无插值）

4. **预乘 Alpha 的重要性**
   - Three.js 默认假设纹理是预乘的
   - PNG 文件通常不是预乘的
   - 需要显式设置 `premultipliedAlpha: false`

5. **诊断工具的价值**
   - 使用 `magick identify -verbose` 分析纹理
   - 检查 alpha 通道的位深度和统计信息
   - 验证假设而不是猜测
