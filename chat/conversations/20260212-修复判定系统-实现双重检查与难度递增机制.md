# 修复判定系统-实现双重检查与难度递增机制

**日期：** 2026-02-12
**项目：** game3 (Sky Scraper 摩天大楼游戏)
**状态：** ✅ 已完成

## 对话概要

### 问题背景
用户发现游戏中出现反直觉现象：楼层明显向右偏移很大，与下方楼层几乎没有重叠（"下方已完全镂空了"），但游戏仍然判定为搭建成功，而不是掉落或触发 Miss。

### 核心问题分析

通过深入分析代码，发现了三个层面的问题：

1. **判定逻辑问题**：使用相对位置（吊臂与塔顶视觉位置的差值）而非绝对位置（新楼层与下方楼层的实际重叠）
2. **视觉偏移问题**：蛇形扭动和着陆旋转的偏移减小了相对偏移值，导致判定失准
3. **倒塌检测缺失**：质心倒塌机制已被禁用，没有累积偏移的惩罚

### 问题场景重现

**场景示例：**
- 塔顶楼层逻辑位置：x = 0
- 蛇形扭动偏移：+1.0 单位（向右）
- 着陆旋转偏移：+0.3 单位（向右）
- 塔顶视觉位置：1.3 单位
- 吊臂位置：2.5 单位
- 计算的相对偏移：1.2 单位
- Miss 判定阈值：2.0 单位
- **判定结果：Okay（不是 Miss）**

但从玩家视角看：
- 实际重叠区域：1.5 单位
- 重叠率：37.5%
- **玩家感知：严重偏移，几乎镂空**

### 解决方案

基于用户反馈，采用了"双重检查机制 + 增强难度递增"的方案，**不使用质心倒塌**（因为玩家无法感知为什么突然倒塌）。

#### 1. 双重检查机制
- 同时检查相对位置判定（追踪视觉位置）和绝对重叠判定（物理合理性）
- 取两者中较差的判定作为最终结果
- 解决视觉偏移导致的判定失准问题

#### 2. Instability 影响吊臂摆动速度
- 吊臂角速度根据 instability factor 动态调整（1.0-2.0倍）
- 效果：塔越歪 → 吊臂摆动越快 → 越难追踪对准

#### 3. Instability 动态收紧判定窗口
- 判定阈值根据平均 instability 动态调整（收紧最多30%）
- 效果：塔越歪 → 判定越严格 → 越容易 Miss

#### 4. 禁用质心倒塌机制
- 保持质心倒塌检测为注释状态
- 使用难度递增代替突然倒塌，因果关系更清晰

### 难度递增路径

```
楼层偏移 → Instability 累积 → 多重难度增加
                ↓
    ┌───────────┼───────────┬───────────┐
    ↓           ↓           ↓           ↓
着陆旋转放大  蛇形扭动放大  吊臂加速    判定收紧
    ↓           ↓           ↓           ↓
 更难对准    塔身晃动加剧  更难追踪    更易失败
```

### 玩家感知

**改进后的体验：**
- 前期：instability 低，吊臂慢，判定宽松，容易成功
- 中期：累积偏移增加，instability 上升，吊臂加速，判定收紧，难度提升
- 后期：instability 很高，吊臂很快，判定很严，非常难成功，最终 Miss 失败

**因果关系清晰：** "塔越歪，吊臂越快，越难对准，判定越严格，最后实在太难了才失败的" 而不是 "不知道为什么突然就倒了"

### 关键代码片段

**双重检查机制：**
```javascript
// 1. 相对位置判定
const relativeResult = Physics.calculateOverlapByOffset(relativeOffset, prevFloor.width, avgInstability);

// 2. 绝对重叠判定
const absoluteResult = Physics.calculateOverlap(floor, prevFloor);

// 3. 取较差的判定
const finalGrade = this.getWorseGrade(relativeResult.grade, absoluteResult.grade);
```

**吊臂动态加速：**
```javascript
const dynamicAngularVelocity = this.angularVelocity * instabilityFactor;
this.position.x = 0 + this.amplitude * Math.sin(dynamicAngularVelocity * this.time) + this.noise;
```

**判定窗口动态收紧：**
```javascript
const instabilityFactor = 1.0 + Math.min(instability, 100) / 100 * 0.3;  // 1.0 - 1.3
const perfectThreshold = 0.05 * W / instabilityFactor;
const greatThreshold = 0.20 * W / instabilityFactor;
const okayThreshold = 0.50 * W / instabilityFactor;
```

## 关键收获

1. **判定系统设计原则**：视觉效果（蛇形扭动、着陆旋转）不应影响判定逻辑，应该分离视觉表现和物理判定
2. **难度递增设计**：通过多层次的难度递增（吊臂加速、判定收紧）代替突然倒塌，让玩家能清楚感知因果关系
3. **双重检查的必要性**：当有多个判定维度时，应该同时检查并取最严格的结果，确保游戏的合理性
