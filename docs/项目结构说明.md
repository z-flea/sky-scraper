## 目录说明

### 📚 docs/ - 文档目录
存放所有项目文档，包括：
- 游戏策划文档
- AI 上下文文档
- 开发会话记录
- 项目说明

### 🧪 tests/ - 测试目录
存放测试相关文件：
- `screenshots/` - 测试过程中的截图
- `.playwright-mcp/` - Playwright 测试配置

### 💻 src/ - 源代码目录
按功能模块组织的源代码：
- `core/` - 核心游戏逻辑（楼层、机械臂、物理）
- `systems/` - 游戏系统（判定、连击、阶段）
- `rendering/` - 渲染相关（场景、相机、特效）
- `ui/` - 用户界面（HUD、菜单）
- `assets/` - 资源加载器代码

### 🎨 assets/ - 游戏资源目录
存放游戏运行时需要的资源文件：
- `sprites/` - 2D 精灵图片
- `textures/` - 纹理贴图
- `audio/` - 音频文件（BGM、音效）
- `fonts/` - 字体文件

### 🌐 public/ - 公共静态资源
存放不需要构建处理的静态文件：
- `index.html` - HTML 入口文件

### 📦 dist/ - 构建输出
Vite 构建后的输出目录（已添加到 .gitignore）

## 文件命名规范

根据项目 CLAUDE.md 规范：
- 文件名使用小写，用下划线连接：`sprite_loader.js`
- 类名使用大驼峰：`class Floor {}`
- 函数名使用小驼峰：`calculateOverlap()`
- API 函数必须以 Api 结尾：`getFloorApi()`

## 开发工作流

1. **开发**: 在 `src/` 目录下编写代码
2. **测试**: 使用 Playwright 进行测试，截图保存到 `tests/screenshots/`
3. **构建**: 运行 `npm run build`，输出到 `dist/`
4. **文档**: 重要的开发记录保存到 `docs/sessions/`

## 注意事项

- ✅ 所有文档统一放在 `docs/` 目录
- ✅ 测试相关文件统一放在 `tests/` 目录
- ✅ 源代码按功能模块组织在 `src/` 目录
- ✅ 游戏资源文件放在 `assets/` 目录
- ✅ `dist/` 和 `node_modules/` 已添加到 .gitignore
- ✅ 测试截图已添加到 .gitignore（避免污染仓库）
