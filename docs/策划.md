游戏策划文档：摩天大楼 (Sky Scraper)

## 1. 游戏概述 (Game Overview)
- 类型： 物理模拟 / 堆叠 / 反应类
- 核心体验： 在不断升高的极端环境中，通过精准的节奏感和物理直觉，维持一座摇摇欲坠的摩天大楼的平衡。
- 开发技术栈： Three.js (渲染) + 自定义轻量级物理逻辑 (核心判定)。

## 2. 核心循环 (Core Loop)

- 摇摆 (Aiming)： 机械臂吊着新楼层在上方左右摆动（摆动中心跟随塔顶）。
- 下落 (Dropping)： 玩家点击，楼层受重力垂直下落。
- 判定 (Judgment)： 计算新楼层与下方楼层的重合度，产生分数与物理后果。
- 平衡 (Equilibrium)： 系统计算大楼局部重心，若重心偏移过大，大楼崩塌；若稳固，则高度+1，进入下一层。

## 3. 详细机制设计 (Game Mechanics)
### 3.1 机械臂摇摆机制 (The Arm Logic)为了保证游戏随着高度增加难度曲线合理，机械臂的运动并非固定在屏幕中心，而是追踪塔顶。

- 运动公式：Xarm(t)=Xpew_floor +A.sin(w·t)+Noise(t)
- X_{prev\_floor}$：上一层楼的中心 X 坐标（关键： 这意味着如果楼歪了，机械臂也会歪过去，迫使玩家手动纠偏）。
- A (振幅)：摆动范围。
- omega (角速度)：摆动快慢。
- Noise (干扰)：模拟风力的随机偏移。

### 3.2 下落与判定系统 (Drop & Judgment)
楼层宽度记为 W。
计算偏差值：Offset = |X_{current} - X_{prev}|

判定等级,触发条件 (偏差范围),分数,物理修正,不稳定性 (Instability),连击 (Combo)
完美 (Perfect),<5%⋅W,+100,磁吸修正：强制 Xcurr​=Xprev​,-10 (大幅回稳),计数 +1
优秀 (Great),5%−20%⋅W,+50,无修正，保留物理位置,+5 (轻微扰动),计数清零
一般 (Okay),20%−50%⋅W,+10,无修正，保留物理位置,+20 (严重扰动),计数清零
失误 (Miss),>50%⋅W,0,楼层掉落,N/A,游戏结束

### 3.3 物理崩塌规则 (Physics & Collapse)
为了兼顾真实感与游戏性，采用“滑动窗口重心法”。不计算整栋楼（几百层）的重心，只计算最近 10 层的局部结构。
- 计算窗口： 取最顶端的 10 层楼层对象。
- 计算合成重心 CoM_{local：CoM_{local} = frac{\sum (Position_i \cdot Mass)}{\sum Mass}
- 获取支撑基座：取窗口下方的第一层（即顶端往下数的第 11 层）作为基座。记其左右边缘为 [Edge_L, Edge_R]。
- 崩塌判定条件：如果 CoM_{local < Edge_L 或 CoM_{local > Edge_R \rightarrow 触发崩塌。
- 表现： 大楼从第 11 层处断裂，上方 10 层受重力倾倒。

### 3.4 连击与稳固系统 (Combo System)鼓励高玩修正大楼。
- 3 Combo (Steady): 消除当前累积的"不稳定性"数值的 50%。
- 5 Combo (Reinforced): 下一层楼层的宽度临时增加 10%（更容易接住）。
- 10 Combo (Architect): 神迹修复。一道光束降下，强制将最近 10 层的 $X$ 坐标全部对齐到中心轴，物理隐患彻底消除。

#### 3.5.3 性能优化策略

**渲染优化:**
- LOD (Level of Detail) 系统:
  - 距离摄像机 > 50层: 使用低模 (50三角形)
  - 距离摄像机 20-50层: 使用中模 (200三角形)
  - 距离摄像机 < 20层: 使用高模 (500三角形)
- 对象池 (Object Pool): 预创建100个楼层对象，循环复用
- 视锥剔除 (Frustum Culling): Three.js自动处理，只渲染可见楼层

**物理计算优化:**
- 只计算最近10层的重心 (滑动窗口)
- 已稳定的楼层 (isStable = true) 不再参与物理计算
- 碰撞检测: 只检测当前下落楼层与最顶层的重叠

**内存管理:**
- 超过200层后，删除最底部的楼层对象 (保留数据用于统计)
- 纹理图集 (Texture Atlas): 所有楼层材质合并到一张2048×2048贴图

#### 3.5.4 碰撞检测算法

```javascript
function calculateOverlap(currentFloor, previousFloor) {
  const curr_left = currentFloor.position.x - currentFloor.width / 2;
  const curr_right = currentFloor.position.x + currentFloor.width / 2;
  const prev_left = previousFloor.position.x - previousFloor.width / 2;
  const prev_right = previousFloor.position.x + previousFloor.width / 2;

  // 计算重叠区域
  const overlap_left = Math.max(curr_left, prev_left);
  const overlap_right = Math.min(curr_right, prev_right);
  const overlap_width = Math.max(0, overlap_right - overlap_left);

  // 计算偏差值
  const offset = Math.abs(currentFloor.position.x - previousFloor.position.x);

  // 判定等级
  const W = previousFloor.width;
  if (offset < 0.05 * W) return { grade: 'Perfect', overlap_width };
  if (offset < 0.20 * W) return { grade: 'Great', overlap_width };
  if (offset < 0.50 * W) return { grade: 'Okay', overlap_width };
  return { grade: 'Miss', overlap_width: 0 };
}
```

### 3.6 边界情况与规则澄清 (Edge Cases)

#### 3.6.1 特殊情况处理

**第一层楼层 (id = 0):**
- 直接放置在地面中心 (x = 0, y = 0)
- 无需判定，自动判定为 Perfect
- 作为后续楼层的参考基准
- 宽度使用初始值 W₀ = 4.0

**恰好边界值的判定:**
- offset = 5.00% × W: 判定为 Great (采用"大于等于"规则)
- offset = 20.00% × W: 判定为 Okay
- offset = 50.00% × W: 判定为 Miss

**连击中断后的状态:**
- 连击数归零
- 不稳定性数值保留 (不清零)
- 临时加宽效果立即失效 (下一层恢复正常宽度)

**Perfect判定的磁吸修正:**
- 触发条件: offset < 5% × W
- 修正行为: 将当前楼层的 x 坐标强制设置为 prev_floor.position.x
- 视觉表现: 楼层在接触瞬间有一个微小的"吸附"动画 (0.1秒缓动)
- 物理后果: 完全消除该层的偏移，不稳定性 -10

**Phase 5 的旋转机制:**
- 楼层在下落过程中绕 Y 轴旋转
- 旋转角度: 随机 ±15° (在下落0.8秒内完成)
- 判定时刻: 以楼层的旋转后的边界框 (Bounding Box) 计算重叠
- 难度提升: 玩家需要预判旋转后的实际位置

#### 3.6.2 崩塌判定的细节

**重心计算的精确规则:**
```javascript
function calculateLocalCenterOfMass(topFloors) {
  // topFloors: 最顶端的10层楼层数组
  let totalMass = 0;
  let weightedX = 0;

  for (let floor of topFloors) {
    totalMass += floor.mass;
    weightedX += floor.position.x * floor.mass;
  }

  return weightedX / totalMass;
}

function checkCollapse(floors) {
  // 至少需要2层才检测崩塌（底层 + 一层）
  if (floors.length < 2) return false;

  let floorsToCheck;
  let baseFloor;

  if (floors.length <= 10) {
    // 10层及以下：检查除底层外的所有楼层
    floorsToCheck = floors.slice(1); // 除了floor 0的所有楼层
    baseFloor = floors[0]; // 底层作为基座
  } else {
    // 超过10层：只检查最顶端10层
    floorsToCheck = floors.slice(-10);
    baseFloor = floors[floors.length - 11]; // 第11层作为基座
  }

  const CoM = calculateLocalCenterOfMass(floorsToCheck);
  const base_left = baseFloor.position.x - baseFloor.width / 2;
  const base_right = baseFloor.position.x + baseFloor.width / 2;

  // 崩塌条件: 重心超出基座边缘
  if (CoM < base_left || CoM > base_right) {
    return { collapse: true, breakPoint: baseFloor.id };
  }

  return { collapse: false };
}
```

**崩塌动画:**
- 断裂点:
  - ≤10层时：在底层（floor 0）处断裂
  - >10层时：在第11层与第12层之间断裂
- 上方楼层: 受重力影响，根据重心偏移方向倾倒
- 倾倒方向: 如果 CoM < base_left，向左倒；反之向右倒
- 倾倒角速度: 初始 ω = 0.5 rad/s，逐渐加速
- 摄像机行为: 切换到慢动作 (timeScale = 0.5)，跟随下坠的楼层

**重要变更说明 (2026-02-07):**
- ❌ 已移除新手保护机制
- ✅ 从第2层开始就会检测崩塌
- ✅ 使用滑动窗口算法：≤10层检查所有楼层，>10层只检查顶部10层

#### 3.6.3 平衡性目标

**玩家能力分层:**
- 新手玩家 (第一次游玩): 目标到达 Phase 2 (20层)
- 普通玩家 (熟悉机制): 目标到达 Phase 3 (50层)

- Phase 1 → Phase 2 转换 (20层): 引入侧风，测试玩家的适应能力
- Phase 3 (50层): 速度加快，测试玩家的反应速度
- Phase 4 (100层): 大幅度慢速摆动，测试玩家的耐心和预判
- Phase 5 (200层): 混沌模式，只有顶尖玩家能够应对

**测试指标:**
- 平均游戏时长: 3-5分钟 (目标: 让玩家在碎片时间内完成一局)
- Perfect率: 新手 10-20%，高手 40-60%
- 平均连击数: 新手 2-3，高手 5-8
- 崩塌原因分布: 60% Miss判定，30% 重心失衡，10% Phase 5特殊机制

## 5. 视觉与反馈 (Visuals & Feedback)
### 5.1 动态摄像机
- 正常状态： 摄像机位于塔顶斜上方 45 度，随高度平滑上升。
- 不稳定状态： 当 Instability 数值升高时，摄像机 Position 增加随机抖动 (Shake)。
- 崩塌瞬间： 摄像机不再上升，而是转为“慢动作 (Time Scale = 0.5)”，跟随断裂的那一截楼层下坠，增强破坏感。

### 5.2 UI 指示器
- 铅垂线 (Plumb Line)： 屏幕左侧显示一根垂直线，代表绝对中心。线上有一个滑动游标，代表当前局部重心 
  - 游标在绿色区域：安全。
  - 游标在红色区域：危险（接近基座边缘）。
- 连击数： 屏幕中央显眼的数字跳动。

## 5.3 音效 (Audio)
