# VSCode Git 使用指南

## 界面布局

```
┌─────────────────────────────────────┐
│  源代码管理 (Source Control)        │
├─────────────────────────────────────┤
│  更改 (Changes)                     │
│  ├─ src/core/game.js         [M]   │  ← M = 修改过的文件
│  ├─ src/ui/hud.js            [M]   │
│  └─ assets/audio/bgm.mp3     [U]   │  ← U = 新文件（未跟踪）
├─────────────────────────────────────┤
│  暂存的更改 (Staged Changes)        │
│  └─ (空)                            │
├─────────────────────────────────────┤
│  [消息框]                           │
│  输入提交消息...                    │
├─────────────────────────────────────┤
│  [✓ 提交] [↻ 同步更改]             │
└─────────────────────────────────────┘
```

## 基本操作步骤

### 1. 查看修改了哪些文件

- 点击左侧的**源代码管理图标**（第三个图标）
- 会看到"更改"列表，显示所有修改过的文件
- 点击文件名可以查看具体改了什么（左边是旧版本，右边是新版本）

### 2. 暂存文件（准备提交）

**方法一：暂存单个文件**
- 鼠标悬停在文件名上
- 点击文件名右边的 **+** 号
- 文件会移动到"暂存的更改"区域

**方法二：暂存所有文件**
- 点击"更改"右边的 **+** 号
- 所有文件都会被暂存

### 3. 提交（保存到版本历史）

1. 在消息框中输入提交信息
   - 例如："添加了音效系统"

2. 点击 **✓ 提交** 按钮（或按 Ctrl+Enter / Cmd+Enter）

3. 提交成功后，"暂存的更改"会清空

### 4. 推送到 GitHub

- 点击 **↻ 同步更改** 按钮
- 或者点击底部状态栏的 **↑** 图标
- 代码会上传到 GitHub

### 5. 查看历史记录

- 点击文件右边的 **时钟图标**
- 可以看到这个文件的所有修改历史
- 点击某个历史记录可以查看当时的代码

## 分支操作

### 查看当前分支

- 看 VSCode 左下角，显示当前分支名（例如：master）

### 创建新分支

1. 点击左下角的分支名
2. 选择"创建新分支"
3. 输入分支名（例如：feature-audio）
4. 按 Enter

### 切换分支

1. 点击左下角的分支名
2. 选择要切换的分支
3. 点击即可切换

### 合并分支

1. 先切换到 master 分支
2. 按 F1 打开命令面板
3. 输入"Git: Merge Branch"
4. 选择要合并的分支

## 常见场景操作

### 场景 1：修改了代码，想提交

```
1. 点击源代码管理图标
2. 查看修改了哪些文件
3. 点击"更改"右边的 + 号（暂存所有文件）
4. 在消息框输入提交信息
5. 点击 ✓ 提交
6. 点击 ↻ 同步更改（推送到 GitHub）
```

### 场景 2：想撤销某个文件的修改

```
1. 在"更改"列表中找到文件
2. 右键点击文件
3. 选择"放弃更改"
4. 文件会恢复到上次提交的状态
```

### 场景 3：提交错了，想撤销

```
1. 按 F1 打开命令面板
2. 输入"Git: Undo Last Commit"
3. 提交会被撤销，但修改会保留
```

### 场景 4：想开发新功能（使用分支）

```
1. 点击左下角的分支名
2. 选择"创建新分支"
3. 输入分支名：feature-新功能名
4. 在新分支上开发
5. 开发完成后，切回 master
6. 合并分支
```

## 快捷键

- **Ctrl+Shift+G** (Mac: Cmd+Shift+G) - 打开源代码管理
- **Ctrl+Enter** (Mac: Cmd+Enter) - 提交
- **F1** - 打开命令面板（可以搜索所有 Git 命令）

## 图标说明

- **M** (Modified) - 修改过的文件
- **U** (Untracked) - 新文件（还没被 Git 跟踪）
- **D** (Deleted) - 删除的文件
- **A** (Added) - 新添加到暂存区的文件
- **C** (Conflict) - 冲突的文件（需要手动解决）

## 提示

1. **经常提交**：每完成一个小功能就提交一次
2. **提交信息要清楚**：方便以后查找
3. **定期推送**：避免本地代码丢失
4. **使用分支开发新功能**：保持 master 分支稳定
