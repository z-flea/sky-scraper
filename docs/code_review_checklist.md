# 代码审查清单（Code Review Checklist）

## 使用说明

每次提交代码前，请按照此清单自查。如果使用PR流程，审查者也应使用此清单。

---

## 📋 通用检查项

### 代码质量
- [ ] 代码符合项目命名规范（小写+下划线）
- [ ] 没有使用 `||` 提供默认值（除非是外部输入）
- [ ] 没有使用 `;(xxx as any)` 绕过类型检查
- [ ] 函数定义使用 `const` 而不是 `function`
- [ ] 注释使用单行注释 `//`
- [ ] 代码简洁，能一行返回就一行返回

### 文档
- [ ] 复杂逻辑有注释说明
- [ ] 公共API有JSDoc注释
- [ ] 如果修改了核心逻辑，更新了相关文档

### 测试
- [ ] 手动测试了修改的功能
- [ ] 没有引入明显的bug
- [ ] 性能没有明显下降

---

## 🎮 游戏特定检查项

### 物理系统
- [ ] 物理参数使用了 `config/physics_params.js` 中的常量
- [ ] 新增参数在 `docs/parameter_history.md` 中记录了
- [ ] 参数有明确的注释说明（单位、范围、物理意义）
- [ ] 没有硬编码魔法数字

### 性能
- [ ] 没有在游戏循环中创建新对象
- [ ] 使用了对象池（如果需要频繁创建/销毁）
- [ ] 避免了不必要的计算（缓存结果）

### 架构
- [ ] 没有创建未使用的函数（死代码）
- [ ] 没有重复实现已有功能
- [ ] 遵循了单一职责原则

---

## 🔧 物理参数修改专项检查

如果修改了物理参数（刚度、阻尼、敏感度等），必须：

1. **记录修改原因**
   - [ ] 在 `docs/parameter_history.md` 中添加了记录
   - [ ] 说明了修改前的值、修改后的值、修改原因

2. **验证影响**
   - [ ] 测试了低层建筑（1-20层）的表现
   - [ ] 测试了中层建筑（20-50层）的表现
   - [ ] 测试了高层建筑（50-100层）的表现
   - [ ] 验证了倒塌阈值是否合理

3. **文档更新**
   - [ ] 更新了 `CLAUDE.md` 中的参数说明（如果有）
   - [ ] 更新了对话记录（如果是重大修改）

---

## 🚨 严重问题检查

以下问题必须立即修复，不能提交：

- [ ] 没有未使用的函数（死代码）
- [ ] 没有重复定义的参数（如两套刚度系统）
- [ ] 没有与设计文档严重不符的实现
- [ ] 没有明显的性能问题（如O(n²)算法）
- [ ] 没有内存泄漏（如未清理的事件监听器）

---

## 📝 提交信息规范

提交信息应遵循以下格式：

```
<type>(<scope>): <subject>

<body>

<footer>
```

**Type类型：**
- `feat`: 新功能
- `fix`: Bug修复
- `refactor`: 重构（不改变功能）
- `perf`: 性能优化
- `docs`: 文档更新
- `style`: 代码格式（不影响功能）
- `test`: 测试相关
- `chore`: 构建/工具相关

**Scope范围：**
- `physics`: 物理系统
- `rendering`: 渲染系统
- `game`: 游戏逻辑
- `ui`: 用户界面
- `crane`: 吊臂系统
- `floor`: 楼层系统

**示例：**
```
feat(physics): 调整建筑摆动阻尼系数

将阻尼系数从2.5降低到0.08，使摆动持续时间更长，
符合设计文档中"缓慢晃动"的要求。

测试结果：
- 20层建筑：摆动持续约8秒
- 50层建筑：摆动持续约12秒
- 100层建筑：摆动持续约15秒

参考：docs/parameter_history.md #2026-02-09-001
```

## 🔄 代码审查流程

### 自查流程（提交前）
1. 运行游戏，手动测试修改的功能
2. 检查控制台是否有错误或警告
3. 按照本清单逐项检查
4. 提交代码

### PR审查流程（如果使用）
1. 审查者按照本清单检查代码
2. 运行代码，验证功能
3. 提出修改建议或批准
4. 合并代码
